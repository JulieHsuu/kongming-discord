# 孔明 Kongming｜Discord 版數位員工

孔明是資策會數位轉型研究院的顧問協作型數位員工。把他加進 Discord 頻道，就能像跟正式同事一樣聊天交辦。他也會看頻道裡的對話，遇到符合職能的事會主動先把工作做好。

| 職能 | 孔明會交出來的東西 |
| --- | --- |
| ① 訪前準備 | 訪前資料包與 60 分鐘訪綱（Word） |
| ② 資料建檔 | 從公司簡介、型錄、名片照片辨識出欄位，建檔並列出缺漏 |
| ③ 訪後更新 | 錄音自動轉逐字稿；從訪談筆記或逐字稿整理出訪談紀錄（Word），附數據、承諾事項與待辦 |
| ④ 流程銜接 | 案件狀態、缺漏資訊、後續事項，以及一段可直接轉傳的回報 |
| 企業研究 | 上網查公司官網、新聞、同業與產業趨勢，推測可能痛點（Word，附來源）；拜訪準備時自動先做 |
| ⑤ 科專提案 | 科專媒合（26 項計畫）、POC 規劃與 KPI（Word）、提案簡報（PowerPoint）、可操作的產品 Demo（HTML，手機可開）、計畫短片（MP4，含字幕與配樂）、科專計畫書草稿（Word，附申請文件檢核表） |

**2.0 版（經 11 輪評審增修）**：孔明定位為「已具備知識的老顧問」，7/24 在公司伺服器上工作。完整功能與使用方式見 [docs/孔明_功能與使用手冊.md](docs/孔明_功能與使用手冊.md)，每一輪評審意見與修改紀錄見 [docs/REVIEW_LOG.md](docs/REVIEW_LOG.md)。重點：

- **認得每個人**：記得每位同事的角色（新人／資深／主管／專家）、職稱、回答偏好、負責方向、手上案件與最近跟他談過的事；小明問就照小明的狀況回答，不會拿別人的案件亂答，指代不清時先列出他的案件請他選。
- **老顧問經驗內建**：8 大產業的常見痛點、打法、KPI 經驗值、必問問題與警訊；訪談、科專審查、計畫書、提案成交的實務眉角（`data/playbooks.json`）。
- **院內知識庫**：說「孔明，把這份收進知識庫」就會存下 SOP、報價規範、範本，之後回答與產出會引用並寫出文件名稱。
- **團隊協作**：待辦可指派給同事、每天私訊催辦；主管有團隊看板；院內協作單位名冊（`/孔明 找專家`）。
- **品質**：簡報、計畫書、開發信完成後自我查核，標出沒有依據、與案件資料矛盾或過度承諾的句子；案件「定案」的事與孔明說過的話會帶進之後的回答，保持一致。
- **業務開發**：採用商機後寫開發信與電話話術、追蹤推進階段，幾天沒聯繫會提醒。
- **7/24 維運**：工作中斷重啟後詢問是否重做、錯誤即時告警到管理頻道、每日健康報告。
- **個資**：第一次互動告知、`/孔明 我的資料` 本人匯出或刪除。

另外還有：

- **效益試算**：投入、持續成本、效益、補助，算出投資報酬率與回收期（Excel，黃色格是假設，可直接改）。
- **結案與案例知識庫**：結案時整理成案例，之後遇到同產業或同痛點的客戶會拿出來參考（`/孔明 案例`）。
- **記住回饋**：同事說「以後訪綱不要超過 15 題」，之後每項工作都照做（`/孔明 偏好` 可以查看或刪除）。
- **工作節奏**：
  - 每個工作日早上發「今日提醒」，內容包含近期拜訪、逾期或快到期的待辦、相關科專截止日、等待確認的事項。
  - 拜訪前一天如果還沒有訪綱，會自動先研究企業、寫好訪綱。
  - 每週五發案件週報（訊息＋Word）給主管。
  - 要設定 `KM_BRIEF_CHANNEL`。

### 每日商機專欄

沒有拜訪行程的日子（預設是近 3 天都沒有拜訪），孔明會在早上 10 點自己寫一篇商機專欄，流程如下：

1. 依團隊方向（`KM_SCOUT_FOCUS`）、受理中的科專和過去的成功案例，挑一個值得主動去推的對象。對象可以是企業，也可以是政府機關、法人或公協會。
2. 研究對象在做什麼。企業會查產品、客戶、規模與近期動態；單位會查業務職掌、施政重點、預算、正在推的計畫，以及對外合作方式。
3. 到政府電子採購網查相關的公開標案，列出預算、截止日和承辦窗口。
4. 整理公開聯絡窗口，例如官網聯絡信箱、公司總機、承辦科室電話、標案公告上的承辦人。每一筆都附來源。
5. 提出方案方向。企業會配上可申請的科專；單位會寫出提案管道（委辦、標案或共同推動）。
6. 在討論串裡附上提案簡報（PPT）和可操作的 Demo。
7. 顧問覺得可以，就按「可以，建立案件」。按「不適合」，孔明會記住並避開類似的推薦；按「再推薦一個」，孔明會換一個對象。

**每位顧問拿到不同的推薦**

孔明會為每位顧問建一份工作輪廓，依下面幾項挑對象：

- 他說過的方向、專長產業、負責地區
- 他經手過的案件
- 他按過「採用」「不適合」「再推薦一個」的紀錄

同一天推薦給不同人的對象不會重複。

- `/孔明 我的方向 方向:中部食品業、製造業 AI 檢測`：設定方向。也可以直接跟孔明說「我主要跑中部的食品業」。
- `/孔明 我的方向 訂閱:開`：每天收到專屬推薦，預設送到私訊；選 `送達:商機頻道` 會改發到頻道並標註你。
- 沒有人訂閱時，孔明每天寫一篇團隊版專欄。
- 工作輪廓只記工作相關資訊。用 `/孔明 我的方向 忘記:all` 可以清除。

也可以隨時叫孔明做：

- `/孔明 商機`
- 「孔明，推薦一家可以去提案的廠商」
- 「孔明，研究一下工業局最近在推什麼、有什麼標案，我們能提什麼」

聯絡資訊只取自官方網站、政府公告與公開標案上的公務聯絡方式。孔明不查、也不推測個人手機、私人信箱或社群帳號。

## 分工

孔明的分工照《孔明》提案的「任務與治理」。

- **可協作執行**：例行數位工作由孔明直接做。
- **需要顧問確認**：重要資料異動（例如員工數 85 → 92）、進入下一個案件階段、要對外使用的產出，孔明都會附按鈕，請同事按下確認。
- **保留真人處理**：聯絡客戶、需求追問、專業判斷、最終決策（含科專送件與簽核）都留給同事，孔明不會代勞。

## 一、在 Discord 建立孔明（約 10 分鐘）

1. 到 <https://discord.com/developers/applications>，按 **New Application**，名稱填「孔明」。
2. 左側 **Bot**：
   - 按 **Reset Token** 複製 Token，等一下貼進 `.env` 的 `DISCORD_TOKEN`。Token 等同密碼，只放在伺服器上，不要貼到聊天室。
   - 打開 **MESSAGE CONTENT INTENT**。沒打開的話，孔明看不到頻道內容，也無法主動做事。
   - 頭像上傳 `assets/avatar.png`（孔明的照片），使用者名稱設成「孔明」。
3. 邀請孔明進伺服器。啟動後，記錄檔會印出一行「邀請連結」，用伺服器管理員帳號打開即可。也可以自己到 **OAuth2 → URL Generator** 勾選：
   - Scopes：`bot`、`applications.commands`
   - 權限：View Channels、Send Messages、Send Messages in Threads、Create Public Threads、Embed Links、Attach Files、Read Message History、Add Reactions、Use Application Commands
4. 在要讓孔明工作的頻道，確認他有「檢視頻道」與「傳送訊息」權限。

> 如果公司原本用 Hermes Agent 的機器人也在同一個伺服器，請替孔明另外建一個 Bot，Token 不要共用，否則兩邊會重複回覆。

## 二、在公司伺服器部署

需要一台 24 小時開機、可以連外網的 Linux 主機，並安裝 Docker 與 Docker Compose。

```bash
# 把這個資料夾放到伺服器上，例如 /opt/kongming-discord
cd /opt/kongming-discord
cp .env.example .env
nano .env          # 至少填 DISCORD_TOKEN 與 ANTHROPIC_API_KEY（或 OPENAI_* 那組）
docker compose up -d --build
docker compose logs -f     # 看到「孔明上線」就完成了
```

- **模型**：預設用 Claude API（`ANTHROPIC_API_KEY` 到 <https://console.anthropic.com> 申請）。要改用公司自架或其他 OpenAI 相容端點，就把 `KM_LLM_PROVIDER` 設成 `openai`，再填 `OPENAI_BASE_URL`、`OPENAI_API_KEY` 和 `KM_MODEL`。
- **對外網址（建議）**：設定 `PUBLIC_BASE_URL` 並用 Nginx 或 Caddy 加上 HTTPS 反向代理到 8787 埠。設好之後，同事在手機上點按鈕就能直接打開 Demo、播放影片；超過 Discord 上傳上限（預設 10 MB）的檔案也會改給連結。連結很長、無法猜到，但沒有登入機制，請只在公司內部使用。
- **資料**：案件、對話紀錄和產出的檔案都存在 `./state`，請定期備份。
- **更新**：改完程式後執行 `docker compose up -d --build`。

不想用 Docker 的話，需要 Node.js 20 以上、ffmpeg 和 Python 3（`pip install fonttools`）：

```bash
npm ci
sudo apt install fonts-noto-cjk fonts-noto-cjk-extra   # 只用來抽出繁體中文字型
npm run fonts
cp .env.example .env && nano .env
npm start
```

## 三、怎麼跟孔明一起工作

**直接找他**：@孔明、私訊他、訊息開頭寫「孔明，」，或在他開的討論串裡回覆都可以。用一句話交辦就好：

- 孔明，下週二要拜訪宏聯精密，先幫我準備訪綱
- （上傳公司簡介 PDF）孔明，幫我建檔
- 孔明，這是今天的訪談逐字稿，幫我整理
- 孔明，這家能提哪些科專？SBIR 什麼時候截止？
- 孔明，針對目檢漏檢的痛點做 POC 跟提案簡報
- 孔明，幫忙寫 SBIR Phase 1 計畫書草稿
- 孔明，做一個可以操作的 Demo、剪一支 90 秒的計畫短片
- 孔明，停（中斷目前的工作，30 分鐘內不主動做事）

**他會自己做事**：在觀察的頻道裡，只要對話停下約 1 分鐘，孔明就會判斷有沒有屬於他職能、做了會明顯幫上忙的工作。例如：

| 同事在聊…… | 孔明會…… |
| --- | --- |
| 「下週要去拜訪大成食品」 | 先把訪綱做好 |
| 「林協理說他們 6 個人目檢、常漏檢」 | 針對痛點做 POC 規劃 |
| 「那幫他們申請 SBIR 吧」 | 寫計畫書草稿，附申請文件檢核表 |
| 貼上會議紀錄、上傳逐字稿 | 整理成訪談紀錄並更新案件 |
| 「要做個影片給老闆看」 | 先問「要我做計畫短片嗎？」，按「好」才做 |

主動做的成果會放進討論串，不會洗版。閒聊、討論還沒有結論、資訊不足、剛做過的工作，他都不會插手。

**斜線指令**（兩組；Discord 每個指令有字數上限，所以分開）：

- 每位同事：`/孔明 說明｜新人導覽｜待辦｜狀態｜案件｜切換｜商機｜商機追蹤｜我的方向｜我的資料｜查客戶｜找專家｜知識庫｜案例｜今日｜偏好`
- 主管與管理員：`/孔明管理 團隊｜成效｜狀況｜模式｜機密｜知識庫移除｜緊急停止｜恢復`
- 英文介面是 `/kongming …` 與 `/kongming-admin …`。

`/孔明管理 模式`：`auto` 符合職能時主動把工作做好（預設）、`ask` 先問大家再做、`off` 只在被叫到時工作。

## 四、控制成本與打擾程度

| 設定 | 作用 |
| --- | --- |
| `KM_WATCH_CHANNELS` | 只觀察指定的頻道 |
| `KM_CONFIDENCE` | 判斷信心門檻，越高越保守（預設 0.72） |
| `KM_DAILY_PROACTIVE_LIMIT` | 每個伺服器每天最多主動做幾次（預設 15） |
| `KM_QUIET_HOURS` | 這段時間不主動做事，例如 `22-7` |
| `KM_AUTO_TASKS`／`KM_ASK_TASKS` | 哪些工作可以直接做、哪些要先問 |
| `KM_MODEL_FAST` | 判斷「要不要做」這一步用的便宜模型，呼叫最頻繁 |

## 五、資料與隱私

- 孔明觀察的頻道內容、上傳的檔案，會送到你設定的模型服務（Claude API 或自架端點）處理。請只讓他進可以這樣處理的頻道。如果不希望某個頻道被看，就把該頻道設成 `/孔明管理 模式 off`，或不要給他那個頻道的權限。
- 群組訊息對孔明來說是「資料」，不是指令。有人要他越過分工（例如代替顧問送件），他會婉拒。
- 完整的資安規範見 [SECURITY.md](SECURITY.md)：存取控制、工作範圍、敏感資料遮蔽、保存期限與稽核紀錄。

## 六、錄音轉逐字稿

直接把錄音檔（mp3、m4a、wav、aac、ogg，或 mp4、mov 影片）丟進頻道，並寫「孔明，這是今天的訪談錄音」。孔明會：

1. 用 ffmpeg 把錄音轉成 16kHz 單聲道，每 10 分鐘切一段。
2. 送到語音辨識端點，得到帶時間碼的逐字稿。
3. 用模型整理成繁體中文，補標點、修正術語、分段，但不刪減內容。
4. 把 `○○_逐字稿.txt` 傳回頻道。
5. 接著自動整理成訪談紀錄（Word），並更新案件資料與待辦。

語音辨識端點二選一，填在 `.env`：

- **OpenAI**：`KM_STT_API_KEY=sk-...`，模型 `whisper-1` 或 `gpt-4o-transcribe`。
- **公司自架（資料不出公司，建議）**：例如在同一台主機跑 faster-whisper server：

  ```bash
  docker run -d --name whisper -p 8000:8000 fedirz/faster-whisper-server:latest-cpu
  # .env
  KM_STT_BASE_URL=http://whisper:8000/v1   # 或 http://主機IP:8000/v1
  KM_STT_MODEL=Systran/faster-whisper-large-v3
  ```

  有 GPU 的話改用 `latest-cuda` 映像檔，速度會快很多。

上限可調：單檔 200 MB、180 分鐘（`KM_STT_MAX_MB`、`KM_STT_MAX_MINUTES`）。一般 Discord 帳號單檔上傳上限是 10 MB，大約 40 分鐘的 m4a；更長的錄音請分段上傳，或升級伺服器的上傳上限。

## 九、常見問題

- **「Used disallowed intents」**：到 Developer Portal 的 Bot 頁面打開 MESSAGE CONTENT INTENT。
- **孔明沒回應**：確認他在該頻道有讀寫權限；用 `docker compose logs -f` 看記錄。
- **斜線指令沒出現**：孔明啟動時會在每個伺服器註冊指令；在 Discord 按 Ctrl+R 重新整理。
- **影片傳不上來**：檔案超過 Discord 上限。請設定 `PUBLIC_BASE_URL` 改用連結，或請孔明做短一點的影片（例如 60 秒）。
