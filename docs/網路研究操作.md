# LiteLLM 網路研究

已設定 `KM_MODEL_SEARCH=gpt-5-search-api`。搜尋使用同一個 LiteLLM 端點和金鑰；研究整理維持 `KM_MODEL`。未指定搜尋模型或將 `KM_WEB_SEARCH=false` 時，OpenAI 相容模式只整理已知資料。

搜尋請求只帶企業名稱及公開研究主題；完整案件資料留在後續整理步驟。機密案件不執行外部搜尋。搜尋與整理都會使用模型額度，搜尋另記為 `research-search` 或 `scout-search` 用量。

## 交辦

```text
@孔明 請研究大成長城企業：官網產品、近期新聞、同業與可能痛點，附來源，產出企業研究 Word。
```

```text
@孔明 下週要拜訪大成長城企業，請先查公開背景，再做一份 60 分鐘訪綱，未知資料標示待補。
```

拜訪準備在沒有網路研究、原研究僅整理已知資料或研究超過 7 天時，自動先研究。要立即更新可直接交辦研究。

`/孔明 商機` 的研究也使用此搜尋方式。

## 檢查結果

- 企業研究 Word 包含查詢時間、來源網址、待確認事項。
- 基本資訊、新聞、公開聯絡窗口的外部網址，需出現在搜尋服務返回的引用來源中；自行編造的來源不列入已查證項目。
- 訪綱包含已有的企業研究來源。
- 搜尋失敗或沒有引用時，會提示未完成即時查證；不靜默改用模型記憶宣稱已搜尋。
- 來源檢核只能確認引用來自本次搜尋，無法自動保證每一句的解讀正確；痛點推測與客戶資料仍需核對。

首次測試請使用真實公開企業名稱。虛構測試公司沒有公開資料，搜尋可能找不到正確對象。

## 驗證指令

```powershell
node test/web-research-run.js
node scripts/check-web-research.js
```

前者使用假服務測試引用、錯誤及機密保護；後者實際查詢公開企業並將 Word 與研究 JSON 存入 `test/live-web-research`，不發送 Discord 訊息、不建立正式案件。

實作介面依據：[LiteLLM Web Search 官方文件](https://docs.litellm.ai/docs/completion/web_search)。
